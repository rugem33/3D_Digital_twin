# 개발 오류와 기능 확인 기록

작성일은 2026-11-16이며 실제 오류·시험의 발생 날짜를 뜻하지 않는다. 원본 실행 로그, 대화의 사용자 관찰, 코드에 구현된 대응, 합성 검사 기록을 구분했다. 현재 정상 동작에 대한 확인은 사용자의 개발자 확인으로 기록한다.

**4~6월 원래 개발 당시 이력 추가 조사:** `개발오류_수정이력_202604-06.md` 참조. 삭제된 5월 개발 문서, 4월 Product/Sprint Backlog, 4~5월 수정 커밋을 추가 확보했다. 아래의 원시 단말 로그 미확보는 당시 문제·수정 문서도 없다는 뜻이 아니다. 날짜가 확인되지 않은 Mago 로그를 4~6월 실행으로 소급하지 않는다.

## 1. 현재 정상 기능의 확인

사용자는 2026-11-16 대화에서 “정상적으로 동작은 다 확인함”이라고 확인했다. 논문 표 4의 GPS·시점, 목적지·경로, 도착 판정은 이를 근거로 `정상 확인(개발자 확인)`으로 기록할 수 있다. 구체적인 단말·빌드·실행 날짜와 자료를 연결할 자리는 유지한다.

이 확인으로 100% 성공률, 전체 오류 대응 성공, 평균 응답시간, 현장 위치 정확도, 일반 사용자의 유용성을 산출하지 않는다. 현재 정상 동작과 과거 특정 경고의 해결 여부도 별개다.

## 2. 원본 Mago 실행 로그에서 직접 확인한 경고

- 위치: `Tiler_Server/data/outputs/<job_id>/mago_stdout.log`.
- 12개 작업 로그가 모두 Mago 1.15.4 실행을 기록한다. 각 로그에서 아래 동일한 피처 3개의 `Is Invalid Polygon.` 경고가 확인된다.
  - `AL_D010_30_20260309.47737`
  - `AL_D010_30_20260309.144715`
  - `AL_D010_30_20260309.161145`
- 경고 출력은 36회이지만 고유 피처는 3개, 경고 유형은 1종이다. 이를 서로 다른 오류 36건 또는 독립 오류 12건으로 집계하지 않는다.
- 예시 원본: `Tiler_Server/data/outputs/0675f8c81c2743eb97e2007f5c187a69/mago_stdout.log`의 31~33행.
- 해당 경고는 입력 형상의 유효성 문제를 알리는 관찰이다. 특정 피처가 복구·제외되었는지, 현재 버전에서 경고가 해소되었는지는 이 로그만으로 확정하지 않는다.

## 3. 대화·개발 기록 및 구현에서 확인한 사례

| 항목 | 확인 근거 | 반영된 대응·조건 | 논문에 쓸 수 있는 범위 |
|---|---|---|---|
| GPS 고도와 표현 지면의 높이 불일치 | 사용자의 과거 설명, 상세 연구 기록 3.1절 | 지형 조회·지면 캐시·눈높이를 이용한 시점 구성 | 관찰된 불일치와 설계 동기. CRS·지오이드·GPS 변동 중 원인 분리나 오차 감소 수치는 미검증 |
| 낮은 상세도 타일에서 상세 타일 탐색 문제 | 사용자의 버그 관련 회고와 terrain.py의 원인·대응 주석, 상세 기록 7절 | z≤4·z=7에 평탄 타일을 적용하는 우회 | 개발 기록상 대응 및 높이 표현의 적용 조건. 원본 지형 오류 로그·비교 실측은 없음 |
| DEM 범위 밖·NoData 조회 | 합성 검사 정의·이전 검사 기록 및 현재 전처리 코드 | 현재는 범위 절단·조회 불가 객체 제외 후 유효 객체로 진행, 유효 객체 부재·검증 오류 시 실패 | 소프트웨어 처리·검증 사례. 실제 단말에서 발생한 오류 횟수로 환산하지 않음 |

| 로컬 Docker 엔진 미실행 | 이전 개발 검사에서 docker_engine 연결 실패 기록 | 당시에는 QGIS GDAL Python과 로컬 JAR로 검증 수행 | 개발 환경의 제약. 현재 서버·앱의 실패나 배포 상태로 일반화하지 않음 |

과거 대화의 “7m 추가”는 현재 코드에서 높이 7m 오프셋으로 확인된 것이 아니다. z=7 타일 계층과 구분한다.

## 4. 실제 발생으로 단정하지 않은 항목

- API 실패·NavMesh 부분 경로·전체 직선 대체, 건물 겹침·GPS 점프, 나침반 경계와 앱 복귀 처리는 코드의 대응 기능이 확인된다. 해당 메시지가 실제 단말에서 발생한 원본 기록은 이번 조사에서 확보하지 못했다.
- SHP와 지형의 높이 일치를 위한 지형 작업 재사용과 Mago 기본 설정의 1.16.3 변경은 현재 구현 사실이다. 어떤 버그가 버전 변경으로 해결됐다는 인과 근거는 별도로 필요하다.
- README의 앱 자동 종료 원인 목록은 OOM·GPU·발열 등의 진단 후보다. 이를 확정된 크래시 원인이나 해결 성과로 작성하지 않는다.
- README의 위치 정확도·응답시간·FPS 목표값은 실측 달성값이 아니다.

## 5. 논문에 반영하는 방식

- Ⅴ장 1절·표 4: 기본 기능의 정상 동작을 개발자 확인으로 반영하고 수치 집계는 미입력으로 유지한다.
- Ⅴ장 4절: 개발 오류·경고의 근거 수준을 구분하여 기술한다. 원본 로그의 폴리곤 경고, 사용자 관찰의 높이 불일치, 코드 주석에 남은 지형 우회를 같은 종류의 정량 실패율로 합산하지 않는다.
- 내부 팀원 평가: 비교 이미지 외에 참가자별 실제 응답·정오·가능한 응답시간과 평가 의견이 필요하다. 이미지로 응답 결과를 대체하지 않는다.
- 타 지역 시험: 새 지역 자료를 실제 적용하고 표시·위치·경로·도착 및 변경 설정·전처리·코드를 기록한다. 지도 카메라를 다른 곳으로 이동한 것만으로 자료 교체 검증을 완료하지 않는다.

## 6. 버전 대응과 원자료 보존

실험 빌드 A(0.1.0)는 논문에서 처음 시험한 빌드에 부여한다. 과거 Mago 작업 로그와 현재 로컬 상태를 자동으로 A에 연결하지 않는다. 실제 시험 순서가 확인되면 해당 코드·빌드·조건과 연결한다.

원본 로그 경로·해시·경고 행번호·작업별 종료 단계는 `개발오류_근거목록_20261116.json`에 기록했다. 사용자 관찰의 상세 근거는 `논문_연구초점_검토_및_보완사항.md` 3·7절과 대화 기록에 있다. 기능 확인 보고일은 기록하되 확인되지 않은 실행 날짜·반복 횟수·성능값을 생성하지 않는다.

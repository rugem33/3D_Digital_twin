## 5. 기여를 구성하는 방법

- **안내 기능 통합:** GPS에서 시점·목적지·경로·도착까지 연결한 지역 적용 사례와 정상·실패 조건.
- **공간자료 활용 절차:** 건물은 공간 표현, 도로는 탐색, DEM은 지면 기준이라는 역할 구분과 변환·배치 방법.
- **재사용 조건:** 자료 추가·교체 시 유지한 코드, 변경한 설정·전처리·장면 작업, 기능 유지 여부의 기록.

기여 문장 후보: “본 연구는 공공 공간자료를 스마트폰 1인칭 안내 환경에 연계하는 시스템을 구현하고, 제한 지역의 적용 사례를 통해 자료 추가·교체 시 재사용 가능한 구성과 별도 준비가 필요한 조건을 제시한다.”
실제로 하지 않은 교체·평가를 완료형으로 쓰지 않는다. 관련 연구 대비 최초성·우월성보다 구현한 적용 절차와 검증 범위를 설명한다.

## 6. 확장 근거를 위한 최소 실험 제안

아직 실행 결과가 없는 제안이다.
1. 동일 DEM 유효 범위와 도로자료 확보 범위에서 기존 소구역 A와 다른 소구역 B의 건물 SHP를 준비한다.
2. 같은 변환 서버·클라이언트를 이용해 적용한다. DEM 해상도·시점 등 비교와 무관한 조건은 고정한다.
3. 입력 범위·출처·좌표계·객체 수·높이 속성과 변경한 파일·URL·설정·전처리·장면·코드를 기록한다.
4. 건물 표시, GPS 시점 갱신, 유효 경로 표시, 도착 판정을 확인하고 영상·로그를 남긴다.
5. 직선 대체·부분 경로·정상 경로를 구분한다. 코드 수정이 필요하면 재사용의 한계로 기록한다.

성공 판정: B가 정상 표시되고, 명시한 변경 범위 안에서 안내 기능이 유지된다.
동일 원자료를 서로 다른 구역으로 나눈 경우 입증 범위는 해당 형식의 공간적 적용 범위 확대다. 다른 공급기관·속성 구조·형식의 호환까지 입증하지 않는다.
건물 로딩만 확인했다면 건물 자료 적용만 확인한 것으로 쓰고, 내비게이션 전체의 지역 확장으로 확대하지 않는다.

## 7. 현재 데이터·높이 조건과 주요 질의 결론

- DEM 원본 격자 간격은 사용자 확정 **90m**다. 앞선 5m 가정은 사용하지 않는다.
- 실험 빌드 시점은 지면 기준 **2m**다. 시야 확보와 사용자 시점의 절충이며 최적값 검증은 아니다. 현재 장면 저장값은 실험 빌드와 별도 확인한다.
- 기존 확인 건물 SHP는 EPSG:5186, DEM은 EPSG:5179였다. 현재 사용할 원본 파일의 메타데이터는 재확인한다.
- 원본 파일을 모두 동일 좌표계로 저장할 필요는 없지만 공통 공간에 표현하는 변환 과정은 일관돼야 한다.
- 수평 좌표계 변환과 수직 기준 변환은 다르다. DEM의 정표고·타원체고 등 수직 기준은 미확인이다.
- 도로 원본에는 높이 속성이 없고 고정 1m로 메시를 구성했다는 사용자 설명이 있다. 탐색용이며 시각적 도로 표현은 지도 이미지를 활용한다.
- 건물 자체 높이와 건물이 놓이는 지면 높이는 다르다. SHP 높이 속성을 지면 표고로 간주하지 않는다.
- GPS 고도 대신 공급된 지형 표면을 참조하는 시점 처리는 화면 배치를 위한 구현이다. GPS 센서의 절대 고도 오차를 보정했다는 증거가 아니다.
- z=7은 미터 높이가 아닌 타일 상세도 계층이다. 과거 확인한 z≤4·z=7 평탄 타일 처리는 우회·운영 조건으로 문서화하고 실제 실험 경로에서의 적용 여부를 확인한다.

## 8. DEM 건물 클램프 구현 수정 이력

앞선 대화에서 로컬 코드에 반영했다. 아래는 변경 이력이며 현재 배포 상태를 의미하지 않는다.

| 파일 | 변경 |
|---|---|
| `Tiler_Server/app/services/dem_clamp_worker.py` | DEM EPSG:4326 전처리, 건물 경계 중심의 bilinear 높이 조회, 범위·NoData·단위·scale/offset 검증 |
| `Tiler_Server/app/services/tiler.py` | 동기 변환의 DEM 전처리 연결, 준비된 DEM을 기존 Mago `-te`에 전달 |
| `Tiler_Server/app/services/jobs.py` | 비동기 변환에도 연결, preparing_dem 상태 추가 |
| `Tiler_Server/app/config.py` | GDAL Python 실행 파일 설정 `GDAL_PYTHON` 추가 |
| `Tiler_Server/Dockerfile` | 시스템 GDAL Python 바인딩 `python3-gdal` 추가 |
| `Assets/RoadTools/Runtime/Mago3DTiler/ShpTo3dTile.cs` | 지정한 DEM 파일 부재 시 오류, DEM·skirt 설명 수정 |
| `Tiler_Server/tests/test_dem_clamp.py` | 전처리·실제 Mago 생성 비교 테스트 추가 |
| `Tiler_Server/README.md` | 조건·산출물·한계·검증 방법 문서화 |

- 기존 Mago 클램프를 활용한 전처리·검증 보완이다. 새로운 클램프 알고리즘 개발로 기술하지 않는다.
- 건물 중심점 높이만큼 전체를 배치한다. 경사면에 맞춰 바닥의 각 정점을 변형하지 않는다.
- 유효 범위 밖·NoData 건물이 있으면 변환을 실패 처리한다. 좁은 DEM이면 SHP를 유효 범위로 잘라야 한다.
- 수직 기준 변환은 수행하지 않는다. 단위 메타데이터가 없으면 m로 가정하고 `metres_assumed`에 기록한다.
- `scaleHeight`는 배율이 아니라 Mago `-sh`의 지중 여유 높이다. 바닥이 지면보다 이 값만큼 아래에 놓일 수 있다.
- 출력의 `dem_clamp_report.json`, `dem_clamp_samples.jsonl`은 전처리 조회 기록이다. 독립적인 현장 고도 정답 자료가 아니다.
- SHP+DEM 건물 변환과 DEM 지형 타일 생성은 별도 경로다. 건물 변환에 DEM을 넣었다고 표시용 지형 타일도 함께 생성되는 것은 아니다.
- 변환 결과 URL을 Cesium에 적용하는 구조이며 Cesium ion에 자동 업로드·등록하는 방식으로 설명하지 않는다.

- 이 메모 작성 시 위 테스트를 재실행하지 않았다. 당시 원격 배포와 Unity 화면 확인은 미완료였으며 현재 상태는 재확인해야 한다.

## 9. 실효성 평가 관련 질의 결론

- 설문은 명확성·예상 유용성·선호를 측정한다. 동작 성공이나 실제 방향 판단 정확도의 대체 자료는 아니다.
- 앱 배포 없이 동일 조건의 영상·실행 화면으로 방향·목적지 판단 정답률과 응답시간을 기록하고 설문을 병행할 수 있다.
- 팀원 평가는 내부 예비평가로 가능하다. 개발 지식·지역 친숙도 편향을 기록하고 일반 사용자 효과로 일반화하지 않는다.
- 건물→지형→지표면 이미지 추가 비교는 그 순서에서의 추가 효과다. 각 요소의 모든 독립 효과를 분리했다고 쓰지 않는다.
- 비교 화면의 장소·경로·시점·표지·길이·정답 정보를 통제하고 순서·기억 효과를 줄인다. 정답은 사전에 정한다.
- 실제 건물과 맞는지 확인하는 공간 표현 점검과, 이용자의 방향 판단·사용성 평가는 구분한다.
- 영상 평가만으로 실제 보행 도착률이나 현장 안전성을 검증했다고 쓰지 않는다.
- 관련 문헌은 상세 기록 19·22절 참조. 각 논문의 대상·방법과 본 비교 조건의 차이를 유지하고 최종 인용 전에 원문을 재확인한다.

## 10. 남은 작업과 재개 순서

1. 실제 실험 빌드·서버 버전·장면 설정, 적용 자료의 범위·출처·좌표계·높이 속성을 고정한다.
2. DEM 클램프 서버 배포 상태와 Unity 실제 표시를 확인한다.
3. A/B 구역을 정해 자료 추가·교체 기록과 기능 검증을 수행한다.
4. 기능별 성공·실패 기준을 먼저 정하고 GPS·경로·도착 로그를 수집한다.
5. 화면 비교 과제·설문을 확정하고 내부 예비평가 및 가능한 참여자 평가를 실시한다.
6. 실측 결과를 `[실측자료 삽입]` 자리에 넣고 위 20매 구성으로 DOCX를 개정한다.

우선순위는 현재 시스템의 학사논문 정리와 근거 확보다. 높이 정확도 연구·전국 서비스·스마트 글래스 구현으로 범위를 임의 확대하지 않는다.

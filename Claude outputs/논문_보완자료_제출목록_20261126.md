# 졸업논문 보완자료 제출 목록

작성일: 2026-11-26. 기준 초안은 `졸업논문_화면평가반영본_20261119.hwp`이다. 본문에 남은 빈칸에 들어갈 자료와 구하는 곳을 위치별로 정리했다. 미측정 값은 임의로 채우지 않는다.

## 1. 확인 필요 5건

### ① 실험 경계 지도와 빌드 식별자 (Ⅰ장 3절 끝)

**경계 지도 1장**에 다음 네 가지를 겹쳐 표시한다. 손으로 그린 표시도 가능하다.

- 건물 SHP 범위
- DEM 유효 범위
- 도로 메시 범위
- 평가 4장면 위치: 정문사거리, 5호관 후문, 제1학생회관, 중앙도서관

지도가 없으면 각 범위의 위경도 최소·최대 값만 제시해도 된다.

**빌드 식별자**

- 6월 GitHub `main`의 커밋 해시
- 빌드 날짜
- Unity·Cesium for Unity 버전
- 앱 버전 코드

로컬 Git에는 6월 커밋이 없으므로 GitHub에서 확인한다.

### ② 자료 상세 식별정보와 최종 빌드 설정 (Ⅲ장 1절, 표 2)

**자료별 정보**: 건물, DEM, 도로, 시설물, 지표면 이미지 각각에 대해 다음 항목을 기록한다.

- 자료명, 제공기관
- 공공데이터포털 URL
- 갱신일, 내려받은 날짜
- 형식, 좌표계
- 객체 수, 높이 속성 열 이름

**빌드 설정값**

- 카메라 눈높이 (2m 적용 여부)
- 건물 높이 입력 (고정값 12인지 속성 열인지), skirt, scaleHeight
- 도착 반경, 재계산 주기
- 사용한 tileset·terrain URL 또는 작업 ID
- 서버의 Mago 버전

### ③ 연결 허용 오차와 도착 판정 조건 (Ⅴ장 1절)

측정값이 아니라 판정 기준이므로 사용자가 정한다.

- 경로 시작점이 현재 위치에서 몇 m 이내면 "연결됨"으로 볼지
- 경로 끝점이 목적지에서 몇 m 이내면 "완전 경로"로 볼지
- 도착 반경 (코드 기본값 15m, 실제 장면값 확인 필요)과 판정 방식 (수평 거리, 1회만 발생)

결과를 본 뒤 기준을 맞추지 않는다. 이미 관찰한 동작과 같은 기준으로 적는다.

### ④ 실험 버전·실행일·재실행 기록 (Ⅴ장 4절, 7개 테스트)

- **방법 A:** 과거에 테스트를 실행한 날짜와 pytest 출력 기록을 찾는다.
- **방법 B:** 현재 소스(Mago 1.16.3)로 `Tiler_Server/tests`를 다시 실행하고 출력 로그와 날짜를 남긴다.
- 둘 다 어려우면 문장을 "이전 개발 단계의 기록"으로 낮추고 placeholder를 지운다.

### ⑤ 원본의 안정적인 식별 속성 (Ⅴ장 3절)

건물 SHP의 DBF에서 건물마다 고유한 ID 열 이름 하나를 확인한다. 예: 건물관리번호, UFID.
범위 절단 후 FID가 바뀌어도 이 값으로 원본 건물과 대응시킬 수 있다.

## 3. 실측자료 3건

1. **Ⅳ장 3절 (GPS·시점 로그)**
   - GPS 수신 간격
   - 높이 조회 성공·실패 횟수
   - 건물 겹침 보정 발생 횟수
2. **Ⅳ장 4절 (경로)**: 경로 요청마다 한 줄씩 기록한다.
   - 출발지와 목적지
   - 경로 출처 (API / 도로 메시 A* / NavMesh / 직선)
   - 결과 분류 (완전 / 부분+직선 / 전체 직선 / 실패)
   - 처리시간
   - 도착 이벤트 횟수
3. **Ⅵ장 2절 (단말 성능)**: 초기 로딩 시간, 프레임, 메모리.

세 항목 모두 별도 로그로 측정해야 한다. 측정 계획이 없으면 수치를 넣지 않고, 문장을 "후속 측정 과제"로 바꾸고 placeholder를 지운다. 3번은 이미 향후 연구 문단에 있으므로 삭제해도 흐름이 자연스럽다.

## 6. 경계 지도 작성을 위해 보낼 자료 (①)

1. **건물 SHP**: .shp, .shx, .dbf, .prj 한 세트 (ZIP 가능). .prj가 없으면 좌표계를 따로 알려준다. 현재 연결 폴더에는 SHP가 없다.
2. **DEM**: 실험에 쓴 파일 하나. 폴더의 `36710.img`, `output_file.tif`, `Tools/_work/wgs84.tif` 중 하나라면 파일명만 알려준다.
3. **4장면 위경도**: 장면별 좌표와 바라본 방향.

- 도로 메시는 Unity 프로젝트(`Assets/NavMesh-dorohe.asset`, `level2.unity`)에서 추출한다. 실험 장면이 `level2.unity`가 아니면 알려준다.
- 결과물은 자료별 범위 좌표표와 경계 지도 그림 1장이다.
- 실제 화면 캡처는 사용자가 추후 별도로 제공한다.
